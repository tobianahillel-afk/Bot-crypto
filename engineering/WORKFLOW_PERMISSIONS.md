# Workflow Permissions — ENG-04.6\n\nENG-04.6 introduces an incremental least-privilege gate for GitHub Actions token permissions.\n\nHistorical lot workflows are inventoried as legacy debt but are not bulk-rewritten in this work unit.\n\nFor every added or modified workflow:\n\n- a top-level permissions declaration is mandatory;\n- write-all and read-all are forbidden;\n- permissions: {} is allowed for workflows that need no token access;\n- explicit read scopes must be recognized by policy;\n- every write scope is denied unless the exact workflow path and scope has a machine-readable approval with a substantive rationale;\n- job-level permissions may narrow the top-level declaration but may not widen it;\n- dynamic or ambiguous permission declarations fail closed.\n\nThe gate is standard-library-only, offline, and zero-cost. Inventory mode reports historical permission debt without blocking the repository.\n\nPolicy: config/governance/workflow_permission_policy_v1.json\nAuditor: scripts/governance/audit_workflow_permissions.py\n
